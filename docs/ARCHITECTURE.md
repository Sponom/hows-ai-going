# How’s AI Going? — Technical Architecture

## Stack (Cloudflare Edge)
- **Frontend:** React 19 + TypeScript + Vite 6 + Tailwind CSS v4
- **2D Map:** `d3-geo` (Natural Earth projection) + `topojson-client` + `world-atlas` (`50m`) + neutral disputed territories overlay (`src/data/disputed-areas.json` built from Natural Earth `ne_50m_admin_0_breakaway_disputed_areas`)
- **Backend API:** Hono on **Cloudflare Workers** (also serves `dist/` via Workers Static Assets)
- **Database:** **Cloudflare D1** (`hows-ai-going-db`)
- **Geolocation:** Built-in Cloudflare `request.cf` metadata (`country`, `city`, `latitude`, `longitude`)
- **Analytics:** Cloudflare Web Analytics (cookie-free beacon in `index.html`) + Cloudflare Workers Observability (`wrangler.jsonc`)

## Database Schema (`migrations/0001_init.sql` – `0004_feedback.sql`)
- `signals` — current anonymous responses:
  - `anon_token_hash` (`UNIQUE`) — SHA-256 hash of a client-generated anonymous token (1 browser = 1 vote, updatable without duplicates).
  - `ip_hash` — SHA-256 hash of `IP + daily_salt` (used only for soft rate-limiting; raw IP is never stored).
  - `country_code`, `city_name`, `lat`, `lng` (coordinates rounded to `0.1°` ≈ 11 km).
  - `level` (`0..3`), `context` (`none | personal | work | both`), `role`, `domains` (JSON array of up to 5 areas), `symptoms` (JSON array of use cases / reasons).
- `signal_history` — append-only timeline log powering the "World then & now" comparison (`12m`, `6m`, `3m`, `now`).
- `feedback` — user feedback submissions (`kind`, `message`, `contact`, `context_json`, `created_at`).

## Baseline Seed (`scripts/seed-baseline.sql`)
Generated by `scripts/generate-seed.mjs` using public 2024–2026 global AI adoption benchmarks: 776 baseline answers and 960 historical events across 33 countries (26 calibrated + 7 low-data calibrating countries).
All baseline rows carry the prefix `anon_token_hash LIKE 'baseline-%'` so they can be filtered or removed cleanly once organic traffic grows.

## API Endpoints
- `GET /api/health` — Worker health check.
- `GET /api/geo` — country/city hint derived from `request.cf`.
- `GET /api/snapshot?role=&symptom=&context=&period=12m|6m|3m|now` — aggregated map data (countries, cities, areas, use cases, latest 20 responses). Cached at the edge (`max-age=15` for `now`, `max-age=60` for historical periods).
- `POST /api/signal` — validates payload, applies soft rate-limiting (20/hour per IP hash in production), upserts `signals`, appends to `signal_history`, and returns a personalized comparison report.
- `POST /api/feedback` — stores feedback messages (rate-limited to 6/hour per IP hash in production).

## Reading Feedback from D1
Via CLI:
```bash
npx wrangler d1 execute hows-ai-going-db --remote --command "SELECT id, kind, message, contact, datetime(created_at/1000, 'unixepoch') AS created_utc FROM feedback ORDER BY created_at DESC LIMIT 50;"
```
Or via Cloudflare Dashboard → **Storage & Databases → D1 SQL Database → `hows-ai-going-db` → Console**.

## Calibration Thresholds ("Signal Strength")
Configured in [`shared/config.ts`](../shared/config.ts):
- **Country:** `< 25` — calibrating, `25–149` — preliminary, `150+` — high confidence.
- **City:** `< 10` — calibrating, `10–49` — preliminary, `50+` — high confidence.

## Deployment to Cloudflare Workers
1. Production D1 database `hows-ai-going-db` is provisioned with migrations `0001–0004` and baseline seed applied.
2. Set production hash salt: `npx wrangler secret put HASH_SALT`.
3. Deploy: `pnpm deploy` → `https://hows-ai-going.sponom.workers.dev`.
