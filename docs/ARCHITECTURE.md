# How’s AI Going? — Technical Architecture

**Production URL:** `https://howsaigoing.org` (deployed automatically from `main` via Cloudflare Workers Builds)

## Stack (Cloudflare Edge)
- **Frontend:** React 19 + TypeScript + Vite 6 + Tailwind CSS v4
- **2D Map:** `d3-geo` (Natural Earth projection) + `topojson-client` + lazy-loaded `world-atlas` (`50m`) + neutral disputed territories overlay (`src/data/disputed-areas.json` built from Natural Earth `ne_50m_admin_0_breakaway_disputed_areas`)
- **Backend API:** Hono on **Cloudflare Workers** (also serves `dist/` via Workers Static Assets)
- **Database:** **Cloudflare D1** (`hows-ai-going-db`)
- **Geolocation:** Built-in Cloudflare `request.cf` metadata (`country`, `city`, `latitude`, `longitude`)
- **Analytics:** Cookie-free Cloudflare Web Analytics + Cloudflare Workers Observability

## Database Schema (`migrations/0001_init.sql` – `0004_feedback.sql`)
- `signals` — current anonymous responses:
  - `anon_token_hash` (`UNIQUE`) — SHA-256 hash of a client-generated anonymous token (1 browser = 1 vote, updatable without duplicates).
  - `ip_hash` — daily salted SHA-256 hash of client IP (used only for rate-limiting; raw IP is never stored).
  - `country_code`, `city_name`, `lat`, `lng` (coordinates rounded to `0.1°` ≈ 11 km).
  - `level` (`0..3`), `context` (`none | personal | work | both`), `role`, `domains` (JSON array of up to 5 areas), `symptoms` (JSON array of use cases / reasons).
- `signal_history` — append-only timeline log powering the "World then & now" comparison (`12m`, `6m`, `3m`, `now`).
- `feedback` — user feedback submissions (`kind`, `message`, `contact`, `context_json`, `created_at`).

## Baseline Seed (`scripts/seed-baseline.sql`)
Generated by `scripts/generate-seed.mjs` using public 2024–2026 global AI adoption benchmarks: 776 baseline answers and 960 historical events across 33 countries (26 calibrated + 7 low-data calibrating countries).
All baseline rows carry the prefix `anon_token_hash LIKE 'baseline-%'` so the `LIVE` ticker filters strictly to organic check-ins and baseline rows can be retired cleanly once organic volume grows.

## API Endpoints & Edge SEO
- `GET /api/health` — Worker health check.
- `GET /api/geo` — country/city hint derived from `request.cf`.
- `GET /api/snapshot?role=&symptom=&context=&period=12m|6m|3m|now` — aggregated map data cached at the edge via `caches.default` (`15s` for `now`, `60s` for historical periods), automatically invalidated for default filters when a new signal arrives.
- `POST /api/signal` — validates payload, enforces same-origin in production, applies daily salted IP rate limits (`5` new / `12` total signals per hour), upserts `signals`, appends to `signal_history`, and returns a personalized comparison report.
- `POST /api/feedback` — stores feedback messages (same-origin enforced; rate-limited to `6/hour` per IP hash in production).
- `GET /robots.txt` & `GET /sitemap.xml` — dynamically generated for the active origin, covering `/`, `/country/:code`, and `/area/:role`.
- Edge `HTMLRewriter` — rewrites `<title>`, `<meta description>`, `<link rel="canonical">`, and Open Graph tags with live D1 stats for country and area deep links.

## Calibration Thresholds ("Signal Strength")
Configured in [`shared/config.ts`](../shared/config.ts):
- **Country:** `< 25` — calibrating, `25–149` — preliminary, `150+` — high confidence.
- **City:** `< 10` — calibrating, `10–49` — preliminary, `50+` — high confidence.
